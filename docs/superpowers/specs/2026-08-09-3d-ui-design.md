# 3D UI — Design Spec

**Sub-project 5 of 6** in the TRON program. Adds the JARVIS-style visual HUD — a rotating particle-sphere orb that reflects TRON's state — layered on top of the tray-icon shell.

## Goal

A centered, always-on-top, 400×400px orb window that spins gently at idle and visibly changes color and behavior with TRON's state: blue while listening, amber while thinking, green while speaking, purple while acting, red (and spinning faster) on error. Toggleable from the tray menu so it's never stuck in the way.

## Rendering approach: vanilla Canvas2D, not Three.js/WebGL library

The reference video showed a golden particle sphere. That's achievable with plain `<canvas>` 2D drawing — points distributed on a sphere (Fibonacci lattice), rotated per frame, perspective-projected to 2D, drawn as small glowing dots. Pulling in Three.js would mean either a CDN dependency (breaks offline / breaks once packaged if the machine has no internet at that moment) or vendoring a large JS library for an effect a few dozen lines of vanilla JS already produces. `orb.html` is fully self-contained — no external script tags, no CDN, no new file to bundle.

## Components

| Component | Responsibility | Notes |
|---|---|---|
| `orb_ui.py` | `OrbUI` — creates a `pywebview` window (frameless, transparent, always-on-top, 400×400, centered) loading `orb.html`. `.start()` runs pywebview's event loop on its own thread (same pattern `TrayUI` already uses for `pystray`). `.on_state_change(state)` calls `evaluate_js("setState('...')")`. `.toggle_visibility()` shows/hides it. | New dependency: `pywebview` — uses Windows' built-in Edge WebView2 runtime, no bundled Chromium. |
| `orb.html` | Self-contained vanilla-JS particle sphere. `setState(name)` is the only entry point Python calls into. Colors reuse the **same 6-state palette** as `tray_ui._COLORS` (white/blue/amber/green/purple/red) so the orb and tray icon always agree. | Resolved via `config.resolve_path("orb.html")` — lives next to the exe like `persona.txt`, user-editable without a rebuild. Not unit-tested (no browser environment in the test suite); the Python wiring around it is. |
| `tray_ui.py` (modified) | Gains an optional "Show/Hide Orb" menu item, wired to a new constructor parameter. Omitted (falls back to Quit-only, current behavior) if the parameter isn't passed — backward compatible with existing callers/tests. | |
| `main.py` (modified) | Constructs both `TrayUI` and `OrbUI`; combines their `on_state_change` methods into one callback passed to `TronStateMachine`. | |

## Data flow

`TronStateMachine._set_state()` (unchanged) calls a single `on_state_change` callback, which `main.py` now composes from `tray.on_state_change` and `orb.on_state_change` — both fire on every state transition, keeping the tray icon and the orb in lockstep.

## Known limitation

No true click-through: making a window pass mouse clicks to whatever's behind it needs raw Win32 `ctypes` calls (`WS_EX_TRANSPARENT`/`WS_EX_LAYERED`), which `pywebview` doesn't expose. At 400×400px centered, the orb can sit over content you're working on. The tray's "Show/Hide Orb" toggle is the mitigation, not a fix — a real click-through implementation is a future upgrade if this proves annoying in practice.

## Testing

`orb_ui.py`'s Python side (window creation args, `on_state_change`'s `evaluate_js` call, `toggle_visibility`'s show/hide logic) is tested with a mocked `webview` module — same pattern already used for `pystray` in `tray_ui.py`'s tests. `orb.html`'s JS logic is not part of the automated suite; visual correctness is verified manually (see the build doc's smoke-test checklist, extended for this sub-project). `tray_ui.py`'s new menu item is tested by asserting it exists when the toggle callback is provided and is absent when it isn't.

## Explicitly out of scope

- True click-through / mouse-passthrough
- Draggable/repositionable orb, resizing, multi-monitor placement logic
- Any interactive controls inside the orb itself (mic icon, close button seen in the reference video) — it's a pure status indicator; all control stays in the tray menu
